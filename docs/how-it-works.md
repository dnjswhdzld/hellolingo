# 동작 방식

기여하는 사람을 위한 자세한 설명입니다. 쓰는 법은 [README](../README.md)에, 왜 이렇게 만들었는지는 [학습 설계와 근거](learning-design.md)에 있습니다.

## 프롬프트 위 영역

카드와 공부 칸은 프롬프트 입력창 바로 위 영역(`AbovePrompt`)에 그립니다.

- 새 프롬프트를 보내도 카드는 지우지 않습니다. 새 카드가 준비될 때까지 이전 카드를 두고, 그 맨 위에 흐린 줄 `다음 문장 옮기는 중…`을 붙입니다.
- 카드를 만들지 못한 프롬프트(모델 호출 실패 등)는 지나갑니다. 이전 카드가 남고 흐린 줄은 사라집니다.
- 이전 프롬프트의 카드가 새 프롬프트의 카드보다 늦게 오면 버립니다. 버린 카드의 표현은 노트에 모으지 않습니다. 화면에 나온 적이 없기 때문입니다.
- 새 세션은 빈 영역으로 시작합니다.
- 카드 위쪽 오른쪽에 단추를 둡니다. `학습하기`(한국어 카드에만), `복습 N`(복습할 표현이 있을 때만), `학습 노트`(노트가 있을 때만). 자리가 모자라면 단추가 다음 줄로 내려갑니다.
- 공부 칸은 학습자가 단추를 눌렀을 때만 열립니다. 열려 있는 동안에는 카드 위쪽 단추를 숨깁니다. 공부 칸의 단추와 키가 겹치지 않게 하려는 것입니다.
- 카드와 공부 칸이 함께 있으면 좌우 반씩 나눕니다. 영역이 70칸보다 좁으면 위아래로 쌓습니다.
- 공부 칸은 새 프롬프트를 보내도, 턴이 끝나도 그대로 둡니다. `닫기`를 눌러야 닫힙니다.
- 들여쓰기는 줄 앞의 공백이 아니라 안쪽 여백(`paddingLeft`)으로 합니다. 좁은 칸에서 줄이 넘쳐도 다음 줄이 같은 자리에서 이어집니다.
- 카드마다 둥근 테두리를 두릅니다. 테두리 안에는 이모지를 쓰지 않습니다. 터미널마다 이모지 폭을 다르게 세서 오른쪽 테두리가 어긋나기 때문입니다.
- 설문이 떠 있으면 영역을 설문에 양보합니다.

## 한국어 카드

```
╭──────────────────────────────────────────╮
│ 영어로는                                 │
│   Fix the null check in the login        │
│   handler.                               │
│   로그인 핸들러에서 null 체크 고쳐줘     │
│   • null check — null 여부 확인          │
╰──────────────────────────────────────────╯
```

- 영어 문장 아래에 내 한국어를 쓴 순서 그대로 둡니다. 같은 뜻의 조각은 같은 색입니다. "Fix"와 "고쳐줘", "in the login handler"와 "로그인 핸들러에서"가 같은 색으로 칠해집니다.
- 색은 서로 잘 구분되는 넷(테마의 `claude`, `permission`, `success`, `autoAccept`)만 씁니다. 그래서 짝도 넷까지 큰 덩어리로 맞춥니다.
- 짝은 색으로만 보여줍니다. 색을 구분하기 어려운 사람을 위한 표시는 아직 없습니다.
- 짝이 없는 말("가", "the" 같은)은 칠하지 않습니다. 한국어 쪽은 흐리게 둡니다. 짝을 두 개도 맞추지 못하면 영어 한 줄과 그 아래 흐린 원문을 보여줍니다.
- 프롬프트가 여러 문장이면 주된 부탁이나 질문 한 문장만 옮깁니다. 그 문장이 길면(40자쯤부터) 부탁하는 부분만 옮깁니다. 옮기지 않은 문장까지 카드에 두면, 옮긴 것처럼 보이고 읽을 것만 늘기 때문입니다.
- 한국어 줄에는 영어로 옮긴 부분만 나옵니다. 붙여넣은 로그, 에러, 코드, 커밋 정보는 빼고, 내가 쓴 그대로(띄어쓰기까지) 잘라 옵니다. 모델이 고른 부분이 프롬프트에 없으면 짝지은 조각들의 범위를, 그것도 안 되면 프롬프트 전체를 씁니다.
- 내 문장에 섞어 쓴 영어 낱말, 브랜치 이름, 파일 경로, 명령어는 문장의 일부로 봅니다.
- 모델에는 프롬프트를 줄바꿈 그대로 보냅니다. 붙여넣은 내용은 보통 제 줄에 따로 있어서, 모델이 내 문장과 가려낼 수 있습니다.
- 핵심 표현(`•` 줄)은 하나입니다. 예문은 카드에 두지 않고 복습의 정답에서 보여줍니다. 이번 일의 주제를 가리키는 말보다, 일을 시키는 말("tell me where", "Check if" 같은)을 먼저 고릅니다. 다른 일을 시킬 때도 다시 쓰기 때문입니다. 영어 문장 안에 있는 것만 씁니다. 표현 낱말의 60% 이상이 문장에 있어야 씁니다. 관사만 다른 "open an MR"과 "open the MR"은 같은 표현으로 봅니다.

## 영어 카드

- 틀린 부분이 있으면 `✗ 틀린 부분`, `✓ 고친 부분`, 쉬운 한국어 이유를 3개까지 보여줍니다. 고칠 곳이 겹치면 좁은 쪽만 둡니다. "run test again"을 고쳤으면, 그 말이 든 문장 전체를 고친 줄은 뺍니다.
- 틀린 부분이 없으면 더 자연스러운 표현 하나와 예문을 보여주고, 표현을 노트에 모읍니다. 이 카드에는 위에 영어 문장이 없어서 예문을 함께 둡니다.
- 원어민이 그대로 쓸 만한 문장은 고치지 않습니다. "Can"을 "Could"로, "the"를 "a"로 바꾸는 것처럼 다르게 말하는 방법은 틀린 곳이 아니라 더 자연스러운 표현으로 보여줍니다. 문법이 틀렸으면 뜻이 통해도 고칩니다.
- 모델 지시문을 바꾸면 [tools/eval](../tools/eval/README.md)로 실제 haiku 카드를 다시 셉니다.

## 표현 노트

- 카드의 핵심 표현이 자동으로 모입니다. 같은 표현은 대소문자와 공백을 무시하고 한 번만 모읍니다.
- 새 표현은 최근 24시간 동안 5개까지만 모읍니다.
- 복습할 때가 된 표현이 10개 이상이면 새 표현을 모으지 않습니다. 복습해서 10개 아래로 내려가면 다시 모읍니다.
- 모으지 않는 동안에도 카드에 핵심 표현은 보입니다. 노트에 들어가지 않을 뿐입니다. 카드마다 그 사실을 적으면 하루 내내 같은 줄이 붙으므로, 까닭은 `/lingo-notes` 맨 위에만 보여줍니다.
- 학습하기에서 연습한 배울 점(`point`)은 위의 두 상한과 상관없이 담습니다. 그 대신 최근 24시간에 모은 수에는 셉니다. 배울 점 노트에는 복습 때 낼 문제(`drills`)를 함께 둡니다. 이미 있는 배울 점이면 새 문제만 더하고(6개까지), 복습 날이 하루보다 늦으면 하루 뒤로 당깁니다.
- 노트는 최근 것 1000개까지 남깁니다.
- 저장 위치는 `~/.claude/plugins/store/` 아래 `hellolingo_`로 시작하는 JSON 파일 하나입니다. 세션이 바뀌어도 남습니다. 여러 세션이 함께 써도 저장소의 최신 노트에 바꾼 것만 더해서 씁니다. 다만 두 세션이 거의 같은 순간에 쓰면 한쪽 변경이 빠질 수 있습니다. 저장소에 동시에 쓰는 것을 막는 방법이 없기 때문입니다.
- 노트를 읽을 때 모양이 틀린 줄은 버립니다. 배울 점과 문제의 모양만 틀렸으면 그 둘만 빼고 핵심 표현처럼 둡니다.

## 공부 칸

### 학습하기

```
╭──────────────────────────────────────────╮
│ 학습하기 · 1/2                           │
│   ~하는 버튼 → a button to ~             │
│     영어는 꾸며 주는 말이 뒤로 가요      │
│   주문 취소하는 버튼 추가해줘            │
│   영어 조각을 순서대로 눌러 보세요       │
│   [ the order ] [ add a button ]         │
│   [ to cancel ]                          │
╰──────────────────────────────────────────╯
```

- 한국어 카드에서 `학습하기`를 누르면, 카드에서 본 한국어(`original`)와 영어를 haiku에 보냅니다(`lessonPrompt`). 모델은 배울 점 하나와 같은 틀의 새 문장 5개를 돌려줍니다. 문장마다 영어를 영어 순서의 조각 셋으로 나누고, 조각마다 한국어 짝을 붙입니다.
- 배울 점은 어순(`order`)과 말 덩어리(`chunk`)만 받습니다. 낱말 고르기는 맞는 답이 여럿이라 받지 않습니다. "[명사]" 같은 꼬리표로 쓴 틀도 버립니다.
- 문제는 `hooks/lessons.ts`의 `parseLesson`이 거릅니다. 조각이 셋이나 넷이 아닌 문제, 첫 조각이 대문자로 시작하지 않는 문제(영어 순서로 주지 않은 답), in, for, when, please처럼 문장 앞으로 옮길 수 있는 말로 시작하는 조각이 있는 문제, only가 든 문제, 똑같은 조각이 둘인 문제, 카드의 문장이나 다른 문제와 같은 문제를 버립니다. 말 덩어리는 문제 문장 안에 그 덩어리가 있어야 합니다. 글자가 없는 조각(끝의 ".")은 앞 조각에 붙입니다.
- 쓸 만한 문제가 하나도 없으면 한 번 더 부릅니다. 그래도 없으면 "이 문장에서는 따로 연습할 곳을 찾지 못했어요"라고 말합니다. 호출 자체가 실패하면 "문제를 만들지 못했어요"라고 말하고, 다시 누르면 다시 부릅니다.
- 만든 학습하기는 카드마다 기억해서(최근 5장), 같은 카드에서 다시 눌러도 부르지 않습니다.
- 지금 푸는 문제는 앞의 둘입니다. 첫 문제는 배울 점, 도움말, 한국어 조각의 색을 보여 줍니다. 둘째 문제는 셋 다 감춥니다. 문제를 끝내면 정답 문장을 같은 색으로 보여 줍니다.
- 도움말 한 줄은 모델에게 받지 않고 종류마다 정해 둔 말을 씁니다. 모델이 쓴 도움말은 가끔 거꾸로 말했습니다.
- 조각 단추는 정답과 다른 순서로 섞습니다. 섞는 순서는 공부 칸 번호와 문장에서 정해져서, 화면을 다시 그려도 바뀌지 않습니다. 단추 글에서는 첫 조각의 대문자와 끝의 문장 부호를 지웁니다(`pieceLabel`). 남은 조각의 키는 늘 왼쪽부터 `1`, `2`, `3`입니다.
- 영어 순서대로 다음 조각이 아닌 것을 누르면 그 문제는 틀린 것으로 끝납니다.
- 푸는 중에도 조각 단추 끝의 `닫기`(`q`)로 그만둘 수 있습니다.
- 모델이 답한 뒤 공부 칸이 아직 그 학습하기일 때만 배울 점을 노트에 담습니다. 문제가 오기 전에 닫았으면 담지 않습니다. 문제는 지금 풀지 않은 것부터 복습하도록 순서를 바꿔 둡니다(`drillsForReview`).
- 만드는 중에 다시 누르면 같은 호출을 함께 기다립니다. 모델을 또 부르지 않습니다.

### 복습

- `복습 N`을 누르면, 복습할 때가 된 표현 하나를 냅니다. 답한 뒤 `다음 복습`을 누르면 다음 표현을 냅니다. 남은 것이 없으면 `닫기`만 남습니다.
- 핵심 표현은 한국어 뜻을 보고 떠올립니다. 정답은 `정답 보기`(`r`)를 누를 때만 나옵니다. 직접 연 퀴즈라서 시간이 지나도 저절로 나오지 않습니다. `o`는 떠올렸어요, `x`는 못 떠올렸어요입니다.
- 배울 점은 노트에 남겨 둔 문제 가운데 맨 앞의 것을 조각 맞추기로 냅니다. 색과 배울 점은 감추고, 끝난 뒤에 보여 줍니다. 맞히면 떠올린 것, 틀리면 못 떠올린 것입니다. 낸 문제는 맨 뒤로 보내서 다음에는 다른 문장이 나옵니다.
- 처음 모은 표현은 하루 뒤에 복습할 때가 됩니다. 떠올리면 3일, 7일, 14일, 30일 뒤로 늘어납니다. 못 떠올리면 다시 하루 뒤부터입니다.
- 복습할 표현이 여럿이면 순서는 이렇습니다.
  1. 낸 뒤에 답하지 않고 넘어간 표현은 맨 뒤로 보냅니다. 넘긴 것끼리는 넘긴 지 오래된 것부터 냅니다.
  2. 나머지는 한 번이라도 답한 표현을 처음 보는 표현보다 먼저 냅니다. 새 표현이 들어와도 3일, 7일 뒤 복습이 밀리지 않게 하기 위해서입니다.
  3. 그 안에서는 아직 낸 적 없는 것, 낸 지 오래된 것, 복습 날이 이른 것 순서입니다.
- 정답을 본 뒤 답하지 않고 공부 칸을 닫거나 다른 칸으로 옮기면, 그 표현은 하루 뒤에 다시 나옵니다. 간격은 늘리지도 줄이지도 않습니다. 떠올렸는지 알 수 없기 때문입니다.
- 복습은 저장된 노트만 쓰므로 모델 호출이 늘지 않습니다.

### 학습 노트

- `학습 노트`를 누르면 공부 칸에 노트 목록을 엽니다. 영어는 가리고 한국어 뜻과 다음 복습 날만 보여 줍니다. 복습할 때가 된 것을 먼저, 그다음은 `level`이 낮은 것부터 둡니다. 8개까지 보이고 키 `1`~`8`로 고릅니다.
- 고른 표현이 복습할 때가 됐으면 복습과 같습니다. 아직이면 연습입니다. 연습에서 떠올렸으면 일정을 그대로 두고, 못 떠올렸으면 내일로 당깁니다(`practiceNote`). 간격(`level`)은 바꾸지 않습니다.

## 학습 기록

- 날마다 카드, 학습하기, 조각 맞추기와 맞힌 수, 복습과 떠올린 수, 3일 넘게 지난 복습과 떠올린 수, 연습 수를 셉니다(`hooks/stats.ts`).
- 노트와 같은 저장소의 `stats` 키에 날짜(UTC 기준 날 수)별로 400일까지 남깁니다. 밖으로 보내지 않습니다.
- `/lingo-notes` 맨 위에 최근 7일을 한 줄로 보여 줍니다. 공부한 날이 없으면 쓰지 않습니다. 3일 넘게 지난 복습이 5번 이상이면 기억률도 적습니다.
- 기록을 못 써도 공부는 그대로 이어집니다.

## `/lingo-notes`

모은 표현과 각각의 다음 복습 날을 패널에 보여줍니다. 영어는 가립니다. 표현을 누르면 공부 칸에서 그 표현을 떠올립니다. 입력창이 빈 채로 `Esc`를 누르거나 `✕`를 누르면 닫힙니다. 새 표현을 모으지 않는 중이면 맨 위에 그 까닭을 한 줄 적습니다. 복습할 때가 된 것부터 나옵니다. 열 때마다 저장소에서 다시 읽어서, 다른 세션이 모은 표현도 보입니다.

노트는 모두 그립니다. 패널보다 길면 Claude Code가 패널을 스크롤합니다. `ctrl+x` `tab`으로 패널에 들어간 뒤 아래 방향키로 내립니다.

## 건너뛰는 프롬프트

다음 프롬프트는 카드를 만들지 않습니다. 레이어는 이전 카드를 그대로 둡니다.

- 10자 미만
- 슬래시 명령
- 알림, 예약 작업, 다른 세션이 보낸 메시지 같은 자동 메시지

## 모델 호출

- 학습할 프롬프트마다 haiku를 한 번 부릅니다. 응답은 800 토큰까지입니다. 20초 안에 답이 없으면 카드 없이 넘어갑니다.
- `학습하기`를 누르면 haiku를 한 번 더 부릅니다. 응답은 1500 토큰까지, 20초까지 기다립니다. 쓸 만한 문제가 없는 답이면 한 번 더 부릅니다.
- 백틱 세 개(`` ``` ``)로 열고 닫은 코드 블록은 빼고, 앞 1500자까지만 보냅니다. `~~~` 블록, 들여 쓴 코드, 닫지 않은 블록은 그대로 갑니다.
- Claude의 답이 끝날 때는 부르지 않습니다. Claude의 답은 읽지도 않습니다.
- 호출은 Claude Code의 `$.model.complete`로 나갑니다. 이 mod는 그 밖의 네트워크 요청을 하지 않습니다.

## 실패해도 본 작업은 그대로

- 훅마다 `.catch`로 원래 흐름을 잇습니다. 학습 기능이 실패해도 프롬프트는 그대로 갑니다.
- 모델 호출은 타이머로 넘겨서, 프롬프트 전송을 기다리게 하지 않습니다.
- 노트를 못 읽거나 못 써도 카드는 그대로 보입니다.

## 고쳐서 보내기

hellolingo는 Claude Code의 mod 기능으로 만들어서, 여기서는 mod라고 부릅니다. 코드는 `hooks/`에, 타입은 `types/`에, 테스트는 `tests/`에 있습니다. `hooks/register.tsx`가 훅을 등록하고 화면을 그립니다. 나머지 파일은 값만 다루는 함수(`cards.ts`, `lessons.ts`, `notes.ts`, `stats.ts`)와 모델에 보내는 지시문(`prompts.ts`)입니다.

### 폴더로 불러와서 써 보기

1. 저장소를 받습니다.

   ```bash
   git clone https://github.com/dnjswhdzld/hellolingo
   ```

2. 받은 폴더를 mod로 불러옵니다.

   ```bash
   claude --plugin-dir ./hellolingo
   ```

   데스크톱 앱 Code 탭처럼 플래그를 줄 수 없는 곳에서는 `~/.claude/settings.json`에 추가합니다.

   ```json
   { "env": { "CLAUDE_CODE_PLUGIN_DIRS": "/path/to/hellolingo" } }
   ```

3. 코드를 바꿨으면 새 세션을 엽니다. 열려 있는 세션은 바뀐 코드를 다시 불러오지 않습니다.

### 확인 명령

받은 폴더 안에서 실행합니다. Claude Code v2.1.311 이상이 필요합니다. 풀 리퀘스트마다 GitHub Actions가 이 세 명령을 돌립니다.

```bash
node tools/check.mjs
```

```bash
claude plugin validate .
```

```bash
claude plugin test .
```

- `tools/check.mjs`는 개인 정보, 문서 링크, 그림 크기, 매니페스트, 학습자 글의 문법 용어, 커밋 메시지를 봅니다.
- `claude plugin test`는 `tests/` 아래의 `*.test.tsx`를 모두 돌립니다. 모델 호출에 가짜 답을 돌려주므로 API를 부르지 않고, 로그인도 필요 없습니다.
- 타입 검사에는 `.claude-plugin/types/`가 필요합니다. Claude Code가 이 폴더를 mod로 한 번 불러오면 만들어 주고, `.gitignore`에 들어 있어서 커밋되지 않습니다. 그 뒤에 `npx --yes -p typescript@5.6.3 tsc -p tsconfig.json`을 실행합니다.
- 모델 지시문(`hooks/prompts.ts`)이나 카드 파서(`hooks/cards.ts`)를 바꾸면, [tools/eval](../tools/eval/README.md)로 바꾸기 전과 후의 실제 haiku 카드를 셉니다. 학습하기 지시문이나 문제를 거르는 코드(`hooks/lessons.ts`)를 바꾸면 `tools/eval/lessons.mjs`로 셉니다. 테스트는 모델 답을 흉내만 내서, 지시문이 실제로 듣는지는 이것으로만 알 수 있습니다. 로그인이 필요합니다.

### 지키는 것

- Claude의 응답, 코드, 커밋 메시지, 파일은 바꾸지 않습니다. 이 mod는 읽기만 합니다.
- 학습 기능이 실패해도 프롬프트는 그대로 지나가야 합니다. 위의 "실패해도 본 작업은 그대로"를 지킵니다.
- 화면에 나오는 글과 모델이 쓰는 한국어는 [글쓰기 규칙](learning-design.md#글쓰기-규칙)을 따릅니다.
- 카드에 줄을 더하는 변경은 그 줄이 배우는 데 어떻게 도움이 되는지 풀 리퀘스트에 적습니다. [하지 않는 것](learning-design.md#하지-않는-것)도 확인합니다.
- 동작을 바꾸면 그 동작을 확인하는 테스트도 같이 고칩니다.
- 화면이 바뀌면 [가이드](guide/README.md)의 화면도 다시 찍습니다. 방법은 [tools/screenshots](../tools/screenshots/README.md)에 있습니다.
- 에이전트와 함께 풀 리퀘스트를 준비한다면 [PR 전 점검](../.claude/skills/pr-check/SKILL.md)을 따르게 합니다. Claude Code는 이 저장소에서 이 스킬을 알아서 씁니다.
